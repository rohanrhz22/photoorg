Business model · Cost sheet

Selling phorg when customers process everything locally

If the face matching, organizing and sharing all run on the customer's own computer, you (the vendor) pay almost nothing per customer — no servers, no GPUs, no bandwidth. This page lists exactly which services you'd still pay for, what they cost, and how to keep it as close to $0 as possible.

1 The key idea: per-customer cost ≈ $0

4 What you can get for $0

Everything that isn't "sign the app" or "take payment" has a solid free tier.

Website / landing free

Cloudflare Pages, Netlify or Vercel host a static marketing + download page at no cost.

Installer hosting free

GitHub Releases (public) serves your .exe/.msi with a CDN for free. R2/B2 if you want it private.

Model files free

YuNet + SFace already download from OpenCV Zoo (GitHub) on first run, or you mirror them on R2 for pennies.

Auto-updates free

A static JSON version manifest on Pages/GitHub; the app checks it and downloads the new signed installer.

Support email free

Cloudflare Email Routing / Zoho free tier for support@yourdomain.

Crash telemetry free

Sentry free tier (optional) to catch errors — no server to run.

Guest sharing free

The Cloudflare quick tunnel runs on the customer's PC — costs you nothing (see next section).

Docs / help free

Same static site, or a free GitHub wiki.

Licence validation free

Reuse your payment provider's licence API — no custom backend needed.

5 Does the online-sharing feature cost you anything?

No — as it stands today it's $0 to you, because it runs from the customer's machine.

✅ Today: free to the vendor

Each customer's app starts its own Cloudflare quick tunnel from their PC. Cloudflare bills nobody for it. Photos are served from the customer's disk. You pay nothing, regardless of how many customers share.

⚠️ When it would cost

Only if you upgrade the experience: a fixed/branded URL (named tunnel needs a Cloudflare account + domain), or you host photos/relaying yourself. For a "sell software, they run it" model, you never need this.

Trade-off to accept: quick tunnels give a random URL each session and aren't guaranteed. That's fine for event sharing. If a customer wants a permanent link, that's a paid add-on they configure — not your cost.

7 The absolute-cheapest setup

1 · Sign the installer

Azure Trusted Signing (~$10/mo). If you truly want $0, you can ship unsigned — but expect SmartScreen warnings that hurt trust and conversions. Signing is the one bill worth paying.

2 · Sell + licence

Lemon Squeezy (merchant of record): checkout, licence keys, and tax handled. No monthly fee — only ~5% per sale.

3 · Host everything free

Cloudflare Pages for the site + update manifest; GitHub Releases for the installer & models.

4 · One domain

~$12/yr at Cloudflare Registrar, with free email routing for support.

5 · Keep sharing local

Ship the existing free quick-tunnel sharing. No vendor-side servers, ever.

6 · Optional $0 extras

Sentry free tier for crash reports; a GitHub wiki for docs.

Bottom line: roughly $11/month fixed (signing + domain) plus ~5–10% of each sale. No servers, no GPUs, no bandwidth bills — because the customer's computer does 100% of the work.
If you skip code signing to hit literal $0: your only costs become the domain (~$1/mo) and payment fees — but Windows SmartScreen will warn users on download, which noticeably lowers trust and sales. Recommended: keep the ~$10/mo signing.

8 The catch: issues & limitations of the "runs on their PC" model

Selling a local-processing desktop app is cheap and private, but it moves several hard problems onto you and the customer. Here's the honest list.

Code & models are on the customer's diskAnything you ship can be inspected, copied, or reverse-engineered. Python especially is easy to decompile (see next section).high
Licence piracyOffline apps can be cracked or keys shared. You can slow this down, never fully stop it.high
"Works on my machine" supportYou support every mix of Windows version, CPU, RAM, antivirus, missing codecs, HEIC, GPU drivers. Hard to reproduce bugs.high
Performance varies wildlyFace matching speed depends on the customer's CPU/RAM. A weak laptop = slow, and you can't fix it from your side.med
Big install sizeOpenCV + models + Python runtime make a 90 MB+ installer. Antivirus false-positives on unsigned PyInstaller exes are common.med
Updates are pull, not pushA bug fix only reaches users who update. Old versions linger; you may support several at once.med
No usage insightLocal & private means little/no telemetry — hard to know what features are used or where it breaks (unless you add opt-in analytics).med
You can't hide secretsAny API key, licence secret, or algorithm constant shipped in the app can be extracted. Never embed a secret you can't afford to leak.high
Model licence termsYuNet/SFace & OpenCV have their own licences; redistributing them commercially means complying with those terms.med
Feature ceilingAnything that genuinely needs a server (cross-device sync, huge shared galleries, central admin) doesn't fit this model.med
Platform trust frictionSmartScreen / Gatekeeper / antivirus can block first-run until reputation builds, hurting conversions.med
The upside you're trading for: near-zero running cost, strong privacy (nothing uploaded), works offline, and no liability for storing customers' photos. For many buyers that privacy story is the selling point.

9 Will my algorithm / code get exposed?

Straight answer: yes, to a determined person — always. Anything that runs on someone else's computer can be reverse-engineered. The realistic goal is to make it not worth their effort, not to make it impossible.

What's actually exposed today

The current app ships as Python (or a PyInstaller .exe). PyInstaller bundles your .pyc byte-code, which tools like pyinstxtractor + a decompiler can turn back into near-original readable Python. So today, your source is effectively readable.

What's NOT your secret anyway

The "algorithm" here is mostly public: YuNet, SFace and OpenCV are open-source models/libraries. Your real IP is the product — the UX, workflow, packaging, brand and support — not a novel face algorithm.

How it shipsHow hard to read your code
Plain Python .pytrivial — it's the source
PyInstaller .exe (today)easy — extract + decompile .pyc
Compiled with Nuitka / Cython → native binaryhard — real machine code, no easy decompile
Sensitive logic rewritten in C/C++/Rust modulevery hard — normal binary reverse-engineering
Critical checks done server-side (licence/validation)not on device — can't be extracted
Golden rule: never ship anything you can't afford to have read — no hardcoded API keys, no server passwords, no licence "master" secret. Treat the client as fully visible.

10 How to make copying not worth it (practical protection)

A layered approach. Each step raises the effort to crack/copy; together they stop all but the most determined.

1 · Compile, don't bundle

Ship with Nuitka (compiles Python to a native binary) instead of PyInstaller. Removes the easy .pyc decompile path.

2 · Native-ify the crown jewels

Move any genuinely secret logic into a C/C++/Rust extension. Even if the Python is read, the core stays opaque.

3 · Code-sign everything

Signing proves authenticity and makes tampered/repackaged copies obvious and untrusted.

4 · Online licence activation

Validate keys against your payment provider (Lemon Squeezy/Keygen) with device binding + periodic re-checks. Beats offline-only keys.

5 · Keep secret checks off-device

If a feature must be protected, gate it behind a small server call. What isn't shipped can't be extracted.

6 · Watermark builds

Embed a per-customer ID so leaked copies can be traced back to the buyer.

7 · Obfuscate as a speed bump

Tools like PyArmor raise the bar for casual snooping — not unbreakable, but cheap deterrence.

8 · Lean on brand + updates

Frequent signed updates, support and trust make the official version more valuable than a stale cracked one.

9 · Right licence + terms

A clear EULA + honoring OpenCV/model licences gives you legal footing against blatant redistribution.

Realistic target: Nuitka-compiled build + code signing + online licence activation stops ~95% of would-be copiers. The remaining few determined crackers exist for every software product on earth — factor a little piracy in as a cost of doing business, and compete on trust, updates and support.

12 Making it "pay to use" — licensing & trial

The recommended shape for phorg: a 14-day free trial, after which only the premium features (FaceFind + online sharing) lock until a licence key is entered. The rest of the app stays usable. No paid services required to start.

The two mechanisms

⏳ Trial (14 days)

On first launch, store a first-run timestamp in ~/.phorg. Each launch checks today − firstRun ≤ 14. During trial everything works and the UI shows "Trial: N days left". After it expires, only premium locks.

🔑 Licence key (offline, signed)

A key is a digitally signed token containing the buyer's name/email + plan. The app has your public key baked in and verifies it locally — no internet needed. Only you (with the private key) can mint valid keys.

PHORG-<base64 payload>-<signature>
  payload  = { name, email, plan, issued, expires? }
  signature = sign(payload, YOUR-PRIVATE-KEY)  ← only you can make this

Anyone can read a key, but changing even one character breaks the signature — so keys can't be forged or edited.

How it plugs into phorg

UI side

An "Activate" screen to paste a key, a "Trial: N days left" badge, and a lock overlay on the FaceFind & Sharing tabs when not entitled.

Server side

The /api/facefind/* and /api/share/* endpoints check an is_entitled() gate and refuse if unlicensed — so hiding the UI can't be bypassed by calling the API directly.

What you (the vendor) do

Once

Generate a keypair. Keep the private key secret (never ship it); bake the public key into the app.

Per sale

Run a small generator to mint a key for the buyer and email it. Lemon Squeezy / Gumroad can automate this delivery.

Anti-tamper & honesty about limits

LayerStopsDoesn't stop
Signed keyFake / edited keys, casual sharingSomeone re-selling their real key

No offline scheme is uncrackable. The goal is to make copying more effort than it's worth for ~95% of users. Combine with Nuitka compiling + code signing (see §9–10).
Upgrade path: when sales grow, swap the offline check for online activation (Lemon Squeezy / Keygen) — same UI, but the key is validated on their server and bound to the device, so one key can't run on many machines. Cost ≈ the ~5% you already pay the payment provider.
Recommended sequence: ship offline signed keys + 14-day trial first (zero cost, works offline) → add online activation once real money is flowing → keep competing on updates & support so the paid build is simply the better one to run.
