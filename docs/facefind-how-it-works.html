Feature Guide · Architecture + Steps

How FaceFind (Face ID) works

FaceFind lets anyone find every photo they appear in — even inside big group shots — from a single selfie. All face detection and matching runs 100% on the host PC using on-device ONNX models; no photo and no selfie is ever uploaded to a cloud service for the matching itself. This page walks the full architecture, the matching pipeline, and every screen the host and guest see.

1 The idea in one minute

Two people, one local web app served straight from the host's machine.

👤 Host (event owner)

Runs phorg, points it at the event folder, and turns on a guest portal. Shares a link or QR code — on the same Wi-Fi, or over a secure internet tunnel. Can also run FaceFind directly for a named guest.

🙋 Guest

Opens the link on a phone, snaps or picks a selfie, taps Find my photos, and downloads every picture they're in — one at a time or as a ZIP. Their originals stay on the host; only copies are downloaded.

Privacy first: the selfie is matched transiently on the host and the event photos never leave the machine except as the direct downloads a guest explicitly requests.

2 Architecture at a glance

A tiny Python standard-library web server, OpenCV face models, and a single-page front-end. The only path that can leave the LAN is the optional Cloudflare tunnel — and only when the host opts in.

3 The matching pipeline

What happens between "Find my photos" and the results grid. This is the core of vision.facefind().

sequenceDiagram
  autonumber
  participant G as 🙋 Guest browser
  participant S as 💻 Server (:8765)
  participant J as 🧵 Job thread
  participant V as 🧠 vision.py (YuNet+SFace)
  participant F as 🗂️ Event folder

  G->>S: POST /api/facefind/selfie (data URL)
  S->>S: decode → save to %TEMP%/phorg_facefind
  S-->>G: { path }
  G->>S: POST /api/share/find/start (token, selfie, threshold)
  S->>J: spawn background job (_JOBS[id])
  S-->>G: { jobId }
  Note over J,V: if models missing → download YuNet+SFace once
  J->>V: embed(selfie) → reference vector (128-D)
  loop every image in folder
    J->>F: read photo
    V->>V: YuNet detects all faces
    V->>V: SFace embeds each face
    V->>V: cosine(face, reference) ≥ threshold?
  end
  V-->>J: matches (sorted by score)
  loop poll
    G->>S: GET /api/cluster/progress (jobId)
    S-->>G: { done, total, phase, clusters }
  end
  G->>S: GET /api/download/zip?job=... (or per-photo)
  S-->>G: ZIP of matched photos

① Detect — YuNet

Every photo is scanned for all face boxes (not just the biggest one), so a guest who's a small face in a crowd still matches. Big images are downscaled to ≤1600px first for speed.

② Embed — SFace

Each detected face is align-cropped and turned into a 128-D unit vector. The selfie becomes one reference vector via embed() (its largest face).

③ Compare — cosine

For each photo, the best dot(face, reference) across its faces is the score. If it clears the threshold (default 0.40) the photo is a match. Results are sorted high→low.

🎯 The strictness slider maps straight to the cosine threshold
UI labelSliderThresholdEffect
Looser30–360.30–0.36More photos, more false positives
Balanced default~400.40Good recall vs. precision
Strict46–520.46–0.52Only very confident matches
Why "all faces"? facefind() calls embed_all() per photo, embedding up to 12 faces, so group shots are covered — unlike single-face embed() used for the reference selfie.

6 Privacy & security model

🔑 Host-header + token guard

The server tells local apart from guest by the HTTP Host header. Guests may only call a small whitelist of endpoints; every host-only action is blocked. The secret token in the link gates access, and it dies when sharing stops.

🧹 Transient selfie

The selfie is saved to %TEMP%/phorg_facefind only to run the match, then used as a reference vector. Uploads are capped (25 MB) and validated.

🏠 Originals never move

Matches are copied for download; your source photos stay exactly where they are.

🌐 Opt-in internet only

Nothing is exposed publicly unless the host ticks "Share over the internet", which routes an HTTPS Cloudflare tunnel to localhost — the matching still runs on-device.
